# Звітність: BigQuery і Looker Studio

Більшість кроків робиться в інтерфейсах Google. У репозиторії лежать готові запити (`analytics/sql/`) і цей опис.

## 1. BigQuery

- [ ] console.cloud.google.com → створи проєкт (наприклад `heywowboy-analytics`).
- [ ] BigQuery → увімкни API. Картка не потрібна: проєкт без білінгу працює в режимі **sandbox**.
- [ ] GA4 → Admin → Product links → **BigQuery links** → Link:
  - проєкт: щойно створений;
  - Data location: **EU**;
  - Export type: **Daily**. Streaming у sandbox недоступний;
  - Include advertising identifiers: вимкнено.
- [ ] Через добу в BigQuery з'явиться датасет `analytics_<property_id>` з таблицями `events_YYYYMMDD`.

**Чи вистачить sandbox.** Ліміти sandbox: 10 ГБ сховища і 1 ТБ запитів на місяць безкоштовно, таблиці живуть 60 днів. Денний експорт GA4 обмежений 1 млн подій на добу. Сайт із кількома тисячами візитів на місяць дає десятки тисяч подій, тобто мегабайти. Обсягу вистачить із великим запасом. Єдине реальне обмеження — 60 днів зберігання. Щоб зняти його, підключи білінг: дані такого розміру лишаться в безкоштовній квоті.

## 2. Запити

У кожному файлі заміни `PROJECT.DATASET` на свій датасет (наприклад `heywowboy-analytics.analytics_123456789`) і за потреби діапазон дат.

| Файл | Що рахує |
| --- | --- |
| `01_sessions_by_channel.sql` | Сесії і користувачі за джерелом, каналом і кампанією |
| `02_funnel.sql` | Воронка: перегляд → `cta_click` → `form_start` → `generate_lead`, з відсотком переходу |
| `03_leads_first_last_touch.sql` | Заявки за first touch і last touch |
| `04_paths_before_lead.sql` | Шлях сторінок перед заявкою |
| `05_consent_share.sql` | Частка трафіку зі згодою і без |

Запити написані за схемою експорту GA4 і перевірені на синтаксис лише очима: доступу до BigQuery в агента немає. Якщо даси сервісний акаунт із роллю BigQuery Data Viewer і Job User, агент проганить їх на реальних даних.

## 3. Дашборд Looker Studio

Створи звіт на lookerstudio.google.com. Джерела даних: GA4 (вбудований конектор), BigQuery (власні запити), Search Console (вбудований конектор), Google Ads (вбудований конектор), Google Sheets (витрати Meta і ліди з CRM).

Спільні фільтри на кожній сторінці: діапазон дат, `utm_source` / канал, кампанія.

### Сторінка 1. Огляд каналів

| Елемент | Показник | Джерело |
| --- | --- | --- |
| Картки | Сесії, користувачі, заявки, коефіцієнт конверсії | GA4: Sessions, Total users, Key events (`generate_lead`) |
| Таблиця | Канал / джерело / кампанія → сесії, заявки, конверсія | BigQuery, `01_sessions_by_channel.sql` |
| Графік за часом | Сесії і заявки по днях | GA4 |
| Кругова | Частка трафіку зі згодою | BigQuery, `05_consent_share.sql` |

### Сторінка 2. Воронка

| Елемент | Показник | Джерело |
| --- | --- | --- |
| Воронка | Перегляд → клік CTA → початок форми → заявка | BigQuery, `02_funnel.sql` |
| Таблиця | Кліки CTA за `cta_location` | GA4, подія `cta_click`, вимір CTA location |
| Таблиця | Помилки форм за `field` | GA4, подія `form_error`, вимір Form field |
| Таблиця | Шляхи перед заявкою | BigQuery, `04_paths_before_lead.sql` |

### Сторінка 3. Вартість ліда по кампаніях

| Елемент | Показник | Джерело |
| --- | --- | --- |
| Таблиця | Кампанія → витрати, кліки, ліди, кваліфіковані ліди, виграні угоди, CPL, вартість кваліфікованого ліда | Blend: витрати + ліди за ключем `utm_campaign` |
| Витрати Google Ads | Cost, Clicks, Campaign | Конектор Google Ads |
| Витрати Meta | Amount spent, Campaign name | Google Sheets (див. розділ 4) |
| Ліди | Кількість контактів за `wb_lt_utm_campaign` і стадією угоди | Google Sheets: експорт з HubSpot |

Щоб blend працював, назва кампанії в рекламному кабінеті має збігатися зі значенням `utm_campaign` у посиланнях. Формат задано в `tracking-plan.md`.

### Сторінка 4. Органічний пошук

| Елемент | Показник | Джерело |
| --- | --- | --- |
| Картки | Кліки, покази, CTR, середня позиція | Search Console, Site Impression |
| Таблиця | Запити → кліки, покази, позиція | Search Console, Site Impression |
| Таблиця | Сторінки → кліки, покази | Search Console, URL Impression |

## 4. Витрати Meta без платних конекторів

Безкоштовного вбудованого конектора Meta Ads у Looker Studio немає. Два способи:

1. **Ручне вивантаження.** Ads Manager → Reports → Export → CSV з розбивкою за днем і кампанією. Колонки: Day, Campaign name, Amount spent, Impressions, Link clicks. Вставляй рядки в аркуш Google Sheets `meta_spend`, підключений до звіту.
2. **Запланований звіт.** Ads Manager → Reports → Create report → Schedule: щотижневий лист із CSV. Дані однаково треба переносити в аркуш руками або скриптом Apps Script, який читає вкладення з пошти.

Обмеження: дані оновлюються не частіше, ніж ти їх вносиш; валюта має збігатися з Google Ads або бути перерахована в аркуші; атрибуція Meta (7 днів клік, 1 день перегляд) відрізняється від GA4, тож конверсії з кабінету Meta не збігатимуться з лідами з CRM. Для CPL бери витрати з Meta, а ліди з CRM.

## 5. Словник метрик

| Метрика | Як рахується | Джерело істини |
| --- | --- | --- |
| Сесія | GA4: унікальна пара `user_pseudo_id` + `ga_session_id` | GA4 |
| Користувач | GA4: унікальний `user_pseudo_id`. PostHog: унікальний distinct ID | окремо в кожній системі |
| Перегляд сторінки | Одна подія `page_view` на маршрут. У PostHog `$pageview` | GA4 |
| Заявка (лід) | Одна подія `generate_lead` = один запис у CRM з унікальним `lead_id` | CRM |
| Запис у waitlist | `join_waitlist`. Входить і в `generate_lead` | CRM |
| Коефіцієнт конверсії | Сесії з `generate_lead` / усі сесії | GA4 |
| CPL | Витрати каналу / кількість лідів каналу в CRM за last touch | Витрати: рекламний кабінет. Ліди: CRM |
| Кваліфікований лід | Угода дійшла до стадії `qualifiedtobuy` | CRM |
| First touch / last touch | Перше і останнє джерело з параметрами кампанії, збережені з заявкою | CRM (`wb_ft_*`, `wb_lt_*`) |
| Частка згоди | Події з `privacy_info.analytics_storage = 'Yes'` / усі події | BigQuery |

### Чому цифри не збігаються

| Розбіжність | Причина |
| --- | --- |
| У CRM заявок більше, ніж `generate_lead` у GA4 | CRM отримує кожну заявку з сервера. GA4 не бачить тих, хто не дав згоди (без неї GTM не вантажиться, моделювання немає), і тих, хто блокує Google |
| У PostHog подій більше, ніж у GA4 | PostHog іде через власний домен, тож блокувальники його не ріжуть. Без згоди на статистику він, як і GA4, нічого не отримує |
| У PostHog користувачів більше, ніж у GA4 | Без згоди PostHog не зберігає ідентифікатор, і кожне завантаження сторінки є новим користувачем |
| Конверсій у Google Ads або Meta більше, ніж лідів у CRM за last touch | Рекламні системи приписують конверсію собі за власним вікном атрибуції, а також рахують перегляди оголошень |
| GA4 показує джерело `(direct)`, а CRM `google / cpc` | CRM зберігає джерело з cookie на 90 днів. GA4 атрибутує сесію |
| Сесії в GA4 не збігаються з кліками в рекламному кабінеті | Клік не завжди стає сесією: сторінка не довантажилась, відмова від cookies, бот |
