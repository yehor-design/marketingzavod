# Бюджет швидкості

Кожен маркетинговий скрипт сповільнює сайт. Тут зафіксовано межу, базові значення і вплив кожного скрипта.

## Бюджет для мобільних

| Метрика | Межа | Де вимірюється |
| --- | --- | --- |
| LCP | ≤ 2,5 с | Speed Insights (реальні користувачі, p75), Lighthouse |
| CLS | ≤ 0,1 | Speed Insights, Lighthouse |
| INP | ≤ 200 мс | Speed Insights. Lighthouse INP не вимірює, тому в CI замінником є TBT ≤ 200 мс |

## Як вимірюється

- **Реальні користувачі:** Vercel Speed Insights (`@vercel/speed-insights`). Компонент стоїть у кореневому layout. Він не використовує cookies і не ідентифікує відвідувачів, тому працює без згоди. Це описано на сторінці Privacy. Щоб дані з'явилися, Speed Insights треба ввімкнути в панелі Vercel: Project → Speed Insights → Enable.
- **Лабораторно в CI:** GitHub Actions, job `lighthouse` у `.github/workflows/ci.yml`. На кожен pull request збирається production-збірка і Lighthouse CI тричі вимірює `/`, `/pricing`, `/contact`. Таблиця з'являється в Summary запуску. Перевищення бюджету дає попередження і не валить збірку.
- **Локально:** `npm run build && npm run lighthouse`, потім `node scripts/lighthouse-summary.mjs`.

CI міряє локальну збірку на раннері GitHub, а не preview-деплой: preview у Vercel може бути закритий авторизацією, і токена Vercel у CI немає. Числа з CI порівнюй лише між собою, а не з вимірами production.

## Базові значення (до трекінгу)

Production, 16 листопада 2026, Lighthouse 12.8.2, мобільна емуляція, медіана з трьох запусків.

| Сторінка | Оцінка | LCP | CLS | TBT | JS (передано) |
| --- | --- | --- | --- | --- | --- |
| `/` | 70 | 7,40 с | 0,000 | 88 мс | 219 КБ |
| `/pricing` | 83 | 3,75 с | 0,000 | 50 мс | 225 КБ |
| `/contact` | 97 | 2,52 с | 0,000 | 1 мс | 217 КБ |

**LCP головної і Pricing перевищує бюджет ще до трекінгу.** Це не наслідок аналітики. Імовірна причина: героїчні зображення малюються на canvas уже після завантаження JS, а головна важить 2,1 МБ. Виправлення виходить за межі задач про трекінг і потребує окремої задачі.

## Стратегії завантаження сторонніх скриптів

| Скрипт | Як вантажиться | Блокує рендер |
| --- | --- | --- |
| GTM (`gtm.js`) | `next/script`, `afterInteractive`. Вбудований рядок до нього лише заповнює `dataLayer` | ні |
| Cookiebot, GA4, Clarity, Google Ads, Meta, LinkedIn | Усередині GTM, тобто після нього | ні |
| PostHog | Динамічний `import()` у `requestIdleCallback`, через власний домен `/ingest` | ні |
| Speed Insights | Компонент Vercel, скрипт `defer` | ні |

Нічого стороннього немає в `<head>` і ніщо не вантажиться синхронно.

## До і після

Таблицю заповнює задача фінальної перевірки (MAR-39). Рядки «після» для сервісів можна виміряти лише тоді, коли їхні ідентифікатори додано у Vercel і контейнер GTM опубліковано.
